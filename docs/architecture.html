Architecture review · target design (ADR 0005–0012 applied)

stdout-design

One render pipeline, multiple front doors. Core owns the Takumi binding, asset resolution, and orchestration. CLI, dev-server, and web-ui are thin clients that all call the same orchestrator — preview equals export by construction, not by convention.

orchestrate/

The only module that imports from assets/, engine/, and cache/ together. Owns the one correct sequence: resolve locale → merge props → resolve fonts → re-validate merged props → derive cache key → check cache → compile → render.

assets/

Single implementation of locale merge and font/lang resolution, replacing what used to be two divergent copies (dev-server's applyLocale and core's mergeLocale / resolveArabicFonts). Memoized per locale id. See Asset Resolution Sub-System.

project/

Single source of truth for studio-project conventions — configPath, templatesDir, localesDir, defaultCacheDir. Replaces five independently hardcoded path literals across core and dev-server.

shared/

Config schema, error codes, logger, types, validation. Zero filesystem or network access, enforced as a layering rule — a future PR adding I/O here is a visible violation, not a judgment call.

Data Flow — Studio Dev

Browser sends props over HTTP. The dev server validates the raw shape, then hands off to the same orchestrateRender() that CLI batch calls — locale merge, font resolution, and post-merge re-validation all happen inside core, once, not inside the Hono handler. File-watch reloads push over SSE, now including locale file changes.

/measure now takes the same input — {templateId, props, locale} — and routes through orchestrateMeasure(), sharing the same locale/font resolution as /render. Previously /measure had no locale field at all, so a measure-then-render preview flow could get dimensions that didn't match what was actually rendered.

A persistent Vite SSR pipeline (vite-node) compiles .tsx templates at runtime. The FileWatcher watches every path returned by resolveProjectPaths() — templates, locales, and config — and invalidates the module cache accordingly.

TemplateLoader

Boots a Vite dev server in middleware mode (no HMR). Config parsing now goes through the shared parseStudioConfig() (used by CLI too), wrapped in TemplateConfigError here versus AppError in core — same validation output, different error type per consumer.

Module cache invalidation

Deletes module from ViteNodeRunner.moduleCache by both file URL pathname and raw path. Now also invoked for locale JSON files on change — previously this path existed (invalidateDataModule) but was never called, so locale edits didn't hot-reload.

FileWatcher

Watches every directory from resolveProjectPaths() — no longer a hardcoded pair of paths that can silently miss a directory. Per-path debounce (200ms) unchanged.

SSE push

Hono streamSSE at GET /events. Browser connects via native EventSource (useSSE hook). 15s keepalive. Unchanged.

One render path, two loading mechanisms

CLI batch and dev-server no longer diverge in what happens once a template is loaded — both call orchestrateRender() / orchestrateMeasure(). The only remaining difference is how the template module itself gets into memory, which is a deliberate, kept difference: dev-server needs live invalidation for hot reload, CLI does not.

SSR (dev-server)
  • ViteNodeRunner.executeFile()
  • Explicit per-file cache invalidation
  • Hot reload via FileWatcher + SSE
Batch (CLI)
  • Raw import(pathToFileURL(...)), memoized per resolved path within one invocation
  • No hot reload — one-shot execution

Both feed the same orchestrateRender(), the same two-stage cache, and the same asset resolver — including caching. CLI batch was never actually uncached; it always went through RenderCache.

Cross-Section — Studio Dev Call Layers

A render request now passes through one additional layer versus before — Orchestration + Assets — sitting between template loading and the Engine. It's a thin coordinating layer, not a second thick one: Engine and Cache remain where the real depth is.

Implementation

openCache — resolves defaultCacheDir via resolveProjectPaths(), replacing three previously independent (and inconsistent — path.resolve vs path.join) path constructions in CLI, batch, and dev-server.
CompileCache — in-memory LRU, configurable max entries (default 100). Unchanged.
MetadataStore — SQLite via Kysely, WAL mode, trigger-maintained totals. Unchanged.
FsStore — atomic writes, size + content-hash verification on read, self-healing on corruption. Unchanged.
EvictionCoordinator — debounced (250ms), lock-coordinated via proper-lockfile. Unchanged.
ConcurrencyLimiter — wraps p-limit. Unchanged.
cache-keys — SHA-256 truncated, null-byte delimiters. Unchanged.

Asset Resolution Sub-System

New in this design. Replaces two independent, drifted implementations — core's mergeLocale / resolveArabicFonts and dev-server's applyLocale — with one module, called by orchestrate/ for every render, from every front door.

Interface

  • resolveAssetsForLocale(localeId, props)
  • → { props, fonts, fontFamilies, lang }

Implementation

Locale merge — one algorithm: override a prop with the locale value only when the value's type matches the existing prop's type. Output is what gets validated downstream — never the pre-merge props.
Font/lang resolution — one locale-classification rule (replaces two independent startsWith("ar") checks), injectable fetch function for testability, memoized per locale id so batch cells don't re-fetch Google Fonts per row.
Fallback behavior — explicit, documented: on fetch failure, returns an empty font set (logged) rather than a zero-byte placeholder font descriptor, so the renderer's own default handling takes over instead of being handed unusable bytes.
Bug fixed — ordering

Dev-server previously validated props, then merged locale data in afterward with no re-validation — a malformed locale file could reach the renderer instead of a 400. Validation now happens once, after merge, inside the orchestrator.

Bug fixed — cross-contamination

Batch previously resolved fonts once per run and applied them to every cell. Per-locale memoization means an en cell in a mixed en/ar batch no longer receives Arabic font data.

What Changed — Bugs Closed by This Design

Each ADR below corresponds to a specific, previously-observed defect, not a stylistic preference. Filenames match docs/adr/.

0005 Four divergent render call sites (CLI single, CLI batch, dev-server render, dev-server measure) collapsed into one orchestrator — closes the dev-server font gap and the measure/render dimension mismatch.
0006 Locale merge and font resolution unified — closes the validate-before-merge bug and the batch font cross-contamination bug.
0007 Project path conventions centralized — closes the locale hot-reload gap (FileWatcher was never told to watch locales/).
0008 Core re-sliced from runtime-target folders (node/, batch/, shared/) to responsibility layers — makes the I/O-free guarantee for shared/ enforceable.
0009 openCache() replaces three independently-written (and mismatched — resolve vs join) cache-directory path resolutions.
0010 Dev-server bootstrap (Bun.serve, signal handling, shutdown) deduplicated between serve.ts and the CLI's dev.ts.
0011 studio render no longer imports and re-hashes the same template file twice per invocation.
0012 Config validation logic shared between CLI and dev-server — same issue-message content regardless of which command surfaced the error, even though the wrapping error type stays intentionally different.

Core: one render pipeline, multiple front doors

Every front door (CLI, dev-server, web-ui, future MCP) renders through @stdout-design/core's orchestrator. Preview == export by construction — there is no second renderer, no second locale-merge algorithm, and no second font resolver to drift. This is the single most important structural decision in the repo, and the ADRs above exist specifically to make it true in practice, not just in the diagram.
